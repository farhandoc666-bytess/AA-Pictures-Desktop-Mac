A&A PICTURES DESKTOP DISTRIBUTION — v1.1.1 (Windows build/test packaging repair)

1. BACKUP WORDPRESS FIRST. Upload AA_Pictures_Desktop_Licensing_v1.1.0.zip as a plugin update, click Replace current, and ACTIVATE/verify. Do NOT delete the existing plugin or licensing records.
2. WordPress -> A&A App Store -> Desktop Licences -> Store page integration: SELECT YOUR REAL EXISTING STORE PAGE, then Save. This appends a download/availability section below the existing checkout. If your theme bypasses the_content, place [aap_desktop_store] in the Store page manually. My Apps /aa-apps/ already displays purchased keys and platform-specific downloads.
3. Build updated Windows installers: extract ZIP; aa-desktop-suite/BUILD-WINDOWS.bat; locate dist/script and dist/media. These are .exe installers, not Python. A&A AI customer-facing text no longer names a provider. EXISTING Windows install can be replaced by the new version; local data should remain in userData.
4. Build universal macOS installers ON A MAC with Node.js LTS and Apple Developer ID certificate. In Terminal: chmod +x BUILD-MAC.command && ./BUILD-MAC.command. For public distribution configure notarization credentials; unsigned Mac builds are TEST-ONLY, use AAD_ALLOW_UNSIGNED_MAC=1 ./BUILD-MAC.command if necessary. Check signing/notarization after build.
5. Upload FOUR artifacts (Windows Script, Mac Script, Windows Media, Mac Media) via Desktop Licences dashboard or Hostinger File Manager into protected directory. Never upload source ZIP as a customer installer, or files into Media Library. If PHP upload max size is too small use File Manager then set exact filenames.
6. Existing A&A customers whose purchases are paid_verified or complimentary will see downloads after payment; admin-issued users also see downloads. Downloads stay protected by verification and nonces. Customers with only Script cannot download Media.
7. Gemini/third-party AI credentials remain on the server; customers see A&A Writing Assistant UI and a neutral but accurate third-party privacy notice. Your public Privacy Policy must specify the actual AI subprocessors and content usage terms accurately.
8. Backend-only Gemini model names and errors are intentionally not exposed in the new public desktop UX. Do not advertise the underlying third-party model as proprietary. The prior WordPress browser Creative Studio UI is a separate plugin and is NOT changed here.
9. Compatible with Windows x64 and Mac universal (Apple Silicon + Intel) build configuration. This package contains source and build scripts, NOT precompiled installers. A Mac host + Apple signing/notarization is required for a trusted public DMG.
10. Back up both WordPress DB and wp-config salts; do not regenerate the RSA private key. Test existing key, reinstall/update same version, paid checkout automatic entitlement, unauthorized download and offline reopening.

OPTIONAL: If you do not have a Mac, upload CONTENTS of aa-desktop-suite (not the containing directory) to a PRIVATE GitHub repository. The included .github/workflows/build-macos.yml runs on a macOS GitHub Actions runner. Configure these repository Secrets: AA_MAC_CSC_LINK (base64 P12), AA_MAC_CSC_PASSWORD, AA_APPLE_ID, AA_APPLE_APP_PASSWORD (Apple app-specific password), AA_APPLE_TEAM_ID. Then Actions > Build signed A&A macOS installers > Run workflow. Download the DMG artifacts privately. Requires a paid Apple Developer membership and valid signing/notarization credentials. Never commit .p12, the private WordPress RSA key, Gemini key, or other secrets.
